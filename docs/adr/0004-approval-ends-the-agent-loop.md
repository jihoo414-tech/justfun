# 승인 카드가 나오면 에이전트 루프를 끝내고, 승인은 Spring이 직접 실행한다

비서가 승인이 필요한 도구를 부르면 Spring은 실행하지 않고 승인 카드를 DB에 저장한다. 그 차례에 카드가 하나라도 생기면 Python AI 서비스는 Claude를 다시 부르지 않고 루프를 끝낸다. 화면에서는 카드가 비서의 답 역할을 한다. 사용자가 승인하면 Claude를 거치지 않고 Spring이 카드에 고정된 값 그대로 실행하고, 결과를 정해진 문구로 대화방에 남긴다.

사용자가 언제 답할지 모르는데 루프를 열어 둔 채 기다리면 연결과 상태 관리가 어려워진다. 승인 후에 LLM이 값을 다시 정하게 하면 승인한 내용과 다르게 실행될 수 있다.

## Considered Options

- **카드를 만든 뒤 Claude를 한 번 더 불러 "카드를 확인해 주세요"라는 답을 받기**: 답이 자연스럽지만, 그 차례에 Claude가 또 다른 도구를 부를 수 있고 호출 비용이 든다. 카드 자체가 무엇을 하려는지 보여 주므로 고르지 않았다.
- **승인 실행 뒤 마무리 답변용 루프를 한 번 더 돌리기**: 처음에는 이렇게 정했다. 하지만 결과를 보고 Claude가 다시 도구를 부를 위험이 있고, 승인 한 건당 호출이 두 배가 된다. 결과는 정해진 문구("금요일 19:00 '민수랑 저녁'을 캘린더에 추가했어요")로 충분해서 바꿨다.

## Consequences

- Python AI 서비스는 상태를 갖지 않는다. 매 루프마다 Spring이 대화 내용, 기억 메모, 그 상황에 허용된 도구 목록, 현재 시각과 시간대를 담아 보낸다.
- Claude가 한 번에 도구를 여러 개 부르면 모두 처리한다. 읽기 도구는 실행하고, 승인이 필요한 도구는 하나마다 카드를 한 장씩 만든다.
- 카드는 대기, 실행 중, 완료, 실패, 거절됨, 만료됨 상태를 가진다.
  - 승인은 "대기 → 실행 중"을 조건부 UPDATE 한 번으로 바꾸고, 그 뒤에 Google을 부른다. 그래서 승인 버튼을 여러 번 눌러도 한 번만 실행된다.
  - Google에 넘기는 일정 ID를 카드 ID로 만든다. 실패한 카드를 다시 시도해도 일정이 두 개 생기지 않는다.
